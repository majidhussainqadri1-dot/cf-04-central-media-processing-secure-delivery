## New confirmed source defect — R290
**Finding:** The `ProviderExitShadowCopyStage::copySegment()` method checked a saved copy's `type`, `id`, `source_key`, SHA256, size, and `status` before accepting an old `copying_unfenced` or `copied_unfenced` checkpoint; but the saved `target_key` was **not** checked there. The independent terminal `verifyComplete()` did validate the canonical target key. Thus an internally forged target key could be accepted by `copySegment()` during both a partial or already completed replay, even though the final full verification would reject it.

**Root cause:** Inconsistent validation of the same stored proof envelope across incremental replay and terminal verification. This is source-level ledger-integrity incompleteness; no live exploitation or data exposure is evidenced.

**Fix:** `sabri-central-media/includes/class-scm-operations.php` commit `f7114bdcd52c9c3d445f7b5a14b64cf289877f26` introduced a single `shadowTargetKey()` derivation shared by copy, replay and verification. `copySegment()` now checks that each existing saved copy binds its computed target key **before** allowing partial progress or accepting completed idempotent replay.

**Mandatory regression:** `tests/review-round-290-shadow-target-key-replay.php` commit `6e3c66cbc29db3773e18831981a6c0b4615568cc` and mandatory gate commit `18aa8e7ccde68b4b6e9571ff96ad587349b96705`. The test stages actual locally encrypted private objects; verifies partial checkpoints, forges a valid-looking target key, rejects next-copy replay before mutating the second target, restores the genuine checkpoint, completes copy, forges a completed checkpoint, rejects completed replay and full verification, then independently re-verifies genuine evidence with no source deletion, provider switch or native owner mapping update.

**Accounting: new confirmed root defects 1; fixed in PR source 1/1; affected named source-control gaps 1/1; new mandatory focused regressions 1; CI jobs 3/3 green on exact source+test HEAD.** This does not count prior audit discoveries, and no production bug can be called fixed without deployed evidence and live re-test.
