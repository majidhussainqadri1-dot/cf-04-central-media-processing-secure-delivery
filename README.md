# CF-04 — Central Media Processing and Secure Delivery

Runtime candidate **1.1.0-rc.3** is the audited successor of the reconstructed 1.1.0-rc.1 source. It is a **partially implemented, fail-closed foundation** evaluated against:

1. the Definitive Master Plan v3.0;
2. the Consolidated All-Chats Directive Register v2.2; and
3. the CF-04 Complete Master Plan v1.0.

## Truthful status

- Specified: complete in the approved CF-04 written plan.
- Coded: **not complete** against all CF04-FR-001 through CF04-FR-033 Must requirements.
- Current source: security-oriented foundations are implemented; substantial processing, lifecycle, provider, recovery and operations capabilities remain missing.
- Packaged: deterministic candidate package generated by CI with manifest, SBOM and checksums for the implemented subset.
- Automated QA: PHP 8.1 and 8.3 tests are green for the implemented subset; they are not proof of full three-plan completion.
- Hostinger staging, real providers, migration, backup/restore, rollback, browser/accessibility/load/security acceptance, Founder approval, live deployment and operational acceptance: pending.

The runtime is disabled by default. No source presence, plugin activation, feature detection or green CI run authorizes production use.

## Implemented foundations

- purpose-bound multipart upload and bounded local assembly;
- private quarantine, signature/MIME checks and mandatory fail-closed external scanner contracts;
- encrypted local private storage with authenticated encryption and integrity verification;
- persisted signed expiring delivery-grant foundations with audience binding and revocation;
- native-domain authorization adapters and object-version checks;
- basic deletion tombstones, download-task records, verified-sender transfer contracts and image/audio workspace envelopes;
- deterministic package generation, manifest, SBOM, checksums and exact-head CI artifacts.

## Known plan-completion blockers

The current candidate does not yet provide the complete mandatory image/audio/video/document processing pipelines, derivative lineage, sandboxed job engine, approved streaming provider for large objects, complete recipient/group transfer assertions, complete session/operation/range/download grant binding, secure HTTP delivery/disposition, public CDN and purge, key rotation, retention execution, governed holds, ordered deletion reconciliation, provider exit, queue fairness, cost controls, repair/reprocess, restore/rebuild or full observability.

## Release safety

The bundled local provider is limited to bounded local assembly. Objects above the configured safe limit fail closed until an approved streaming assembly, scanning, storage and delivery provider is implemented and accepted on staging. This avoids an unsafe memory claim, but it also means the declared 1 GiB transfer contract is not yet operationally complete.
